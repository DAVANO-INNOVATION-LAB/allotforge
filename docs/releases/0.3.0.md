# AllotForge 0.3.0 development prerelease

AllotForge is the new product name. This release adds explainable GPU, CPU and memory planning while keeping existing deployments compatible.

## Added

- Optional CPU millicore and memory MiB inputs for single-node workload-fit checks.
- Compute request accounting across all bound nonterminal Pods, including CPU-only work, init containers, restartable sidecars and overhead.
- Per-node eligible, blocked and unknown explanations, with source and observation time visible in the UI.
- Conservative unknown results for unsupported Pod-level resource budgets, in-place resize evidence and malformed/missing quantities.
- Synthetic demo scenarios for a complete fit, CPU contention and missing CPU evidence.
- AllotForge interface/API branding and an `allotforge` command alias. Existing `davano` module/command, configuration, labels and CRD names remain unchanged.

## Fixed

- Corrected the GPUAccessPolicy subject namespace guard to use Kubernetes CRD CEL reserved-field escaping. Real API-server CI checks subject allow/deny cases without weakening restrictions.

- Replaced an unsupported native Pod-overhead CEL reference with a conservative RuntimeClass restriction. Managed GPU namespaces now reject RuntimeClass on all new Pods, including CPU-only Pods. Kubernetes RuntimeClass admission must remain enabled; see the control-plane prerequisites.

## Boundaries

This is a development prototype. Fit is advisory request accounting, not reservation, live utilization, admission or GPU execution. No live GPU cluster, exporter, competitor or production deployment was tested. MIG/shared resources remain outside whole-GPU fit/control. Native API-server CI is distinct from GPU hardware testing. Historical CPU benchmark files are 0.2.0 evidence and were not regenerated for this release.

See RELEASE-VERIFICATION.md for the checks run and verification limits. No container image is published. License selection remains pending; no open-source license grant is asserted.
