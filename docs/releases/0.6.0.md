# AllotForge 0.6.0 development prerelease

## Added

- A read-only Workload advisor with CPU, memory and recognized GPU request budgets for every observed Pod, including CPU-only work. Requests remain separate from measured usage.
- Optional bounded CPU, memory-working-set and GPU-busy observations from a separately supplied trusted container-runtime attribution adapter. Exact current Pod/container identities, supported resource mode, freshness, sample coverage and aligned time windows are required.
- Conservative suggestions for a controlled CPU comparison, with the paired-window decision basis and a repeatable benchmark checklist. CPU activity in unrelated containers and multi-GPU averages cannot establish a candidate. No winner, speedup or cost saving is claimed.
- Clear insufficient, stale, conflicting and unsupported evidence states. No automatic moves, resizes, migrations, submissions, pricing lookup or background time-series storage.

## Corrected

- Exact integer GPU quantity parsing no longer rounds a near-integer fractional value into an accepted request.
- Malformed Pod phase values and deeply nested metric responses fail closed without exposing raw structures or collapsing otherwise usable inventory.
- Browser inventory responses are tied to the current administrator session. Credential changes/disconnects invalidate old snapshots and pending results rather than showing evidence from an earlier authorization state.

## Requirements and limits

**The custom attribution adapter is required and is not bundled.** These input gauges are not stock DCGM/cAdvisor/AMD exporter metrics. Relabeling device-wide measurements cannot establish workload attribution. The advisor checks a collector's assertions against observed runtime identities; it cannot independently prove process/device measurement correctness.

A CPU-comparison candidate is only an experiment suggestion. Each GPU-bearing container must request exactly one verified whole GPU, with no unclassified nonzero accelerator requests. CPU/GPU samples must cover the same aligned observation window. Workload portability, correctness, performance and cost still require repeated matched trials. A 15-minute window is not a whole-job profile.

Live telemetry, actual GPU hardware, target collector behavior and native browser interaction were not validated. API doubles, local transport checks, DOM tests and labeled static previews are not hardware certification. Existing exact-commit Kubernetes admission/diagnostic parser CI is a separate regression gate, not workload execution evidence.

See docs/workload-advisor.md for the adapter contract, thresholds, aggregation rules, access boundary and experiment checklist. Existing davano module/configuration compatibility is retained. License selection remains pending.
