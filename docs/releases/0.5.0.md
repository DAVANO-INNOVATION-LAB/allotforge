# AllotForge 0.5.0 development prerelease

## Added

- On-demand deployment diagnostics that work independently of inventory loading and make no external calls in demo mode.
- A separate administrator gate for all live diagnostic reads, including when cluster control and project execution are disabled. Project credentials cannot authorize these checks.
- Bounded, fixed GETs for inventory list access, configured dependency API discovery and an optional constant Prometheus query. No target selectors, writes, access-review POSTs, installations or permission changes.
- Explicit separation of configured, observed, disabled, blocked, unavailable and unverified evidence, with practical next steps. No aggregate production-ready badge or score.
- A dedicated UI with credential-safe request cancellation, stale-report handling, unavailable states and access while inventory is down.
- A disposable-Kubernetes parser/discovery smoke in the exact-commit release gate, in addition to unit, transport-double and UI tests.

## Verification and limits

The diagnostic parser smoke uses fixed kubectl GETs under the existing disposable CI identity, not the application's HTTPS credentials. It checks real Node/Pod list and native/managed discovery response shapes and an absent Kueue dependency. It does not establish target-cluster RBAC, application authentication/transport, Kueue operation, CNI behavior or GPU compatibility. Those boundaries remain separately tested or unverified as described in RELEASE-VERIFICATION.md.

A successful narrow read is not full inventory, write authorization, controller reconciliation, admission enforcement, workload execution or hardware validation. Discovery advertises API operations; it does not grant them. The optional constant Prometheus query reads no exporter series. Report time budgets are checked between operations, not guaranteed operating-system cancellation deadlines. Invalid startup configuration still fails fast.

See docs/deployment-diagnostics.md for authentication, exact limits and interpretation. Existing davano module/configuration compatibility is retained. License selection remains pending.
